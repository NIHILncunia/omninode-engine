# 비로그인 헤더 관리자 로그인 버튼 설계

## 목적

로그인하지 않은 방문자가 상단 헤더에서 관리자 인증 진입점을 즉시 인지하고 `/signin`으로 이동할 수 있게 한다. 로그인한 경우에는 기존 관리자 정보 표시를 유지한다.

## 범위

- `AdminInfoBlock`이 인증 상태에 따라 로그인 관리자 정보 또는 로그인 버튼 하나를 렌더링한다.
- 비로그인 버튼은 Element Plus `ElButton`을 사용한다.
- 버튼에는 톱니 아이콘과 `관리자 로그인` 라벨을 표시한다.
- 버튼은 Nuxt 내부 경로 `/signin`으로 이동한다.
- 검은색 계열 헤더 위에서 포인트 색상 `blue-500`이 명확히 드러나도록 기본·hover·focus 상태를 정의한다.

푸터의 검은색 테마 전환과 전체 사이트의 광범위한 상용 UI 재설계는 이번 범위에서 제외한다.

## 구조

`app/layouts/default.vue`는 현재처럼 `AdminInfoBlock`만 렌더링하고 인증 상태 분기를 알지 않는다. `AdminInfoBlock`은 `auth.store`의 `admin`을 기준으로 다음 두 상태를 책임진다.

| 인증 상태 | 렌더링 | 동작 |
| --- | --- | --- |
| 로그인됨 | 관리자 아이콘, 이름, 이메일 | 기존 표시 유지 |
| 비로그인 | 톱니 아이콘, `관리자 로그인` 버튼 | `/signin`으로 클라이언트 라우팅 |

버튼은 `NuxtLink`와 `ElButton`을 조합하여 전체 버튼 영역을 내부 링크로 제공한다. 버튼의 시각적 기본값은 `blue-500`, hover는 한 단계 진한 파랑, focus는 파란 focus ring으로 둔다. Element Plus의 버튼 요소를 사용해 키보드 포커스와 버튼 스타일 기반을 유지한다.

## 검증

- 로그인 상태 테스트는 관리자 이름과 이메일이 계속 노출되는지 확인한다.
- 비로그인 상태 테스트는 `관리자 로그인` 라벨, 톱니 아이콘, `/signin` 링크를 확인한다.
- 대상 Vitest와 `git diff --check`를 실행한다.

## 완료 기준

- 비로그인 헤더 우측에 파란색 `관리자 로그인` 버튼이 표시된다.
- 버튼 클릭 또는 키보드 활성화로 `/signin`에 이동한다.
- 로그인 상태에서는 버튼 대신 기존 관리자 정보가 표시된다.
- 영향 범위 테스트가 통과한다.
