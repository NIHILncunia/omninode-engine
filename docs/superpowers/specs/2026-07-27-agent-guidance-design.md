# 에이전트 운영 지침 설계

## 목적

이 템플릿을 기반으로 새 앱을 개발할 때 에이전트가 일관된 설계, 구현, 검증 절차와 Nuxt 프로젝트 구조를 따르도록 한다.

## 작업 분류

- 변경 대상 파일이 하나면 경량 작업으로 분류한다.
- 변경 대상 파일이 둘 이상이면 비경량 작업으로 분류한다.
- 파일 수는 실제 수정, 생성, 삭제 대상의 합계로 판단한다.
- 경량 작업도 변경 전후의 영향 범위와 최소 검증은 확인한다.

## 비경량 작업 절차

1. 앱의 목적, 사용자, 핵심 문제와 완료 기준을 마스터에게 확인한다.
2. `superpowers:brainstorming`으로 해결 방향과 범위를 정리하고 설계 승인을 받는다.
3. `superpowers:writing-plans`으로 구현 계획을 작성한다.
4. 승인된 계획에 따라 구현한다.
5. 영향 범위에 맞는 테스트, 린트, 타입 검사 또는 빌드를 실행해 결과를 확인한다.
6. 검증 결과와 변경 범위를 보고한다.

## 템플릿 시작 원칙

이 저장소는 범용 앱 템플릿이다. 새 기능 개발이나 앱 구축을 시작하기 전에는 곧바로 화면이나 기능을 만들지 않는다. 먼저 만들 앱의 성격과 범위를 묻고, 브레인스토밍을 통해 콘셉트와 우선순위를 정한다.

## 문서 역할

- 루트 `AGENTS.md`는 모든 작업에서 우선 읽는 운영 규칙이다.
- 설계와 구현 계획은 `docs/superpowers/` 아래에 기록한다.
- `references/` 아래 Markdown 파일은 사용자가 제공한 요구사항, 조사 자료, 외부 참조와 같이 개발 중 확인할 자료를 보관한다.
- 에이전트가 작성한 분석이나 정리도 마스터가 향후 참고할 가치가 있다고 판단할 때에만 `references/`에 보관한다.
- `AGENTS.md`에는 지속적으로 적용되는 규칙만 두고, 개별 기능의 상세 근거는 설계 문서 또는 참고 문서에 둔다.

## 구현 규칙 범위

루트 지침에는 Nuxt 디렉터리 구조, 페이지와 렌더링 컴포넌트의 분리, CVA와 `cn()` 사용, 데이터 및 설정 파일 규칙, Luxon 사용, 상호작용 함수 명명, Pinia, 검증 및 커밋 규칙을 포함한다.
