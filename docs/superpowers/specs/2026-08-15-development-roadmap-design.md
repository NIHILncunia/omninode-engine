# Omninode 1차 개발 로드맵 및 진행 대장 설계

## 1. 목적

Omninode를 관계형 세계관 관리 시스템의 1차 목표까지 순차적으로 구현한다. 이 문서는 기능의 의존 순서와 공통 완료 기준을 정의하며, 루트 `TODO.md`를 세션 간 진행 상태의 단일 기준으로 운영한다.

## 2. 확정 기준

- 1차 목표는 프로젝트와 월드 안에서 카테고리와 템플릿을 정의하고, Markdown 설정 문서를 작성해 의미 있는 문서 관계를 저장·탐색할 수 있게 하는 것이다.
- 모든 기능은 화면, API, 권한, 입력 검증, 테스트를 함께 완료하는 수직 슬라이스로 구현한다.
- 개발·운영 데이터베이스는 PostgreSQL 단일 Drizzle 스키마와 각각의 `DATABASE_URL`을 사용한다.
- 인증 진입 경로는 `/signin`이며 `app/pages/signin.vue`가 기준이다. `/login`은 사용하지 않는다.
- API 응답은 `CreateResponse`의 `error`, `data`, `code`, `message` 계약을 기준으로 통일한다. 목록 데이터의 페이지 정보는 `data` 내부에 둔다.
- 문서의 영구 본문 정본은 `documents.content` 하나다. 관계 기반 표현은 별도 원본 데이터를 저장하지 않고 문서·관계 데이터를 조회해 도출한다.
- 리비전, 비교, 롤백, 토론, 공개 뷰어, 실시간 공동 편집, 복잡한 감사 로그 화면은 1차 범위에서 제외한다.

## 3. 진행 대장 운영 방식

`TODO.md`는 모든 개발 단계의 상태를 표시하는 단일 기준이다.

- 구현을 시작하기 전 해당 단계와 항목을 `[ ]`로 두고, 선행 조건을 충족했는지 확인한다.
- 항목은 실제 구현·테스트·검증이 끝난 경우에만 `[x]`로 변경한다.
- 차단된 작업은 체크하지 않고 `현재 상태`에 원인과 재개 조건을 기록한다.
- 기능별 상세 설계·구현 계획은 `docs/superpowers/`에 작성하고, TODO에는 해당 문서 경로와 완료 조건을 연결한다.
- 새 세션은 `TODO.md`의 `현재 상태`와 가장 이른 미완료 단계부터 읽고 시작한다.

## 5. 공통 수직 슬라이스 기준

각 기능 단계는 다음 순서를 지킨다.

1. 화면·API 입력과 출력 계약, 권한 범위, 데이터 규칙을 확정한다.
2. 계약을 검증하는 실패 테스트를 작성한다.
3. 저장소·서비스·API를 구현한다. 서비스는 행 간 제약과 소프트 삭제 접근 차단을 트랜잭션으로 검증한다.
4. 페이지는 메타 설정과 데이터 조합만 맡기고, UI는 목적별 컴포넌트에서 구현한다.
5. 로딩, 빈 상태, 오류 상태, 권한 거부, 저장·삭제 확인 절차를 구현한다.
6. 대상 테스트, 전체 테스트, 린트, 타입 검사, 빌드를 실행한다. 기존 무관 실패는 원인과 변경 범위를 분리해 기록한다.
7. `TODO.md`를 갱신하고, 의미 단위 커밋을 남긴다.

## 6. 기준 정합화 범위

단계 0은 구현 전제의 충돌을 해소한다.

- `test/admin-route-scaffolding.test.ts`의 `app/pages/login.vue` 기대값을 `app/pages/signin.vue`로 정정한다.
- `references/옴니노드_UI_API_통합_작업_설계서.md`의 SQLite 개발 환경·방언 병기·SQLite 검증 표기를 PostgreSQL 단일 기준으로 정정한다.
- 같은 문서의 성공·목록·오류 응답 예시를 `CreateResponse` 계약과 일치시킨다.
- `server/db/client.ts` 및 환경 변수 예시를 마련하고, `/api/health`로 연결·응답 계약을 검증한다.
- 인증 store·middleware와 공통 로딩·오류·빈 상태 UI는 다음 인증 슬라이스가 재사용할 최소 인터페이스만 제공한다.

## 7. 검증과 기록

모든 완료 선언은 해당 단계에서 새로 실행한 검증 결과로 뒷받침한다.

```text
pnpm test
pnpm lint
pnpm exec vue-tsc --noEmit
pnpm build
```

데이터베이스 구조를 변경하는 단계는 PostgreSQL Drizzle 생성과 마이그레이션 검증을 추가한다. 데이터베이스 연결·적용은 별도의 사용자 승인과 안전한 대상 확인 뒤에만 수행한다.

## 8. 문서 간 역할

- `references/`: 제품 정의, 사이트맵 후보, 통합 구현 기준의 원본 참고 자료다.
- `docs/superpowers/specs/`: 승인된 설계 결정과 범위를 기록한다.
- `docs/superpowers/plans/`: 한 단계의 실행 가능한 세부 구현 계획을 기록한다.
- `TODO.md`: 현재·다음 작업과 전체 진척도를 추적하는 단일 운영 대장이다.
