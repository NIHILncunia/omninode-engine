# 문서 공통 레이아웃 설계

> 파일명은 기존 문서 목록 설계의 연속성을 유지하지만, 이 문서는 문서 목록과 문서 상세가 공유하는 공통 레이아웃을 정의한다.

## 1. 목적

문서 공통 레이아웃은 옴니노드의 모든 문서를 탐색하고 읽는 화면에 사용한다.

문서 목록 페이지와 문서 상세 페이지는 별도 레이아웃을 사용하지 않는다. 상단 헤더와 기본 본문 컨테이너를 공유하며 본문 영역 내부의 페이지 구성만 달라진다.

문서 관리는 프로젝트 대시보드의 문서 메뉴와 프로젝트 레이아웃에서 수행한다.

## 2. 기본 경로

| 경로 | 처리 | 레이아웃 |
|---|---|---|
| `/` | `/docs`로 리다이렉트 | 해당 없음 |
| `/docs` | 모든 월드·프로젝트의 문서 탐색 | 문서 공통 레이아웃 |
| `/docs/:documentId` | 문서 상세 조회 | 문서 공통 레이아웃 |
| `/worlds/:worldId/projects/:projectId/documents` | 프로젝트 문서 관리 | 프로젝트 레이아웃 |

별도의 `/manage/documents` 경로는 만들지 않는다.

## 3. 공통 레이아웃

```text
문서 공통 레이아웃
├─ 상단 헤더
│  ├─ 옴니노드 로고
│  ├─ 문서 검색
│  └─ 사용자 메뉴
└─ 본문 컨테이너
   └─ 현재 페이지 콘텐츠
```

| 영역 | 내용 |
|---|---|
| 로고 | `/docs`로 이동 |
| 문서 검색 | 모든 문서 또는 현재 선택 범위 검색 |
| 사용자 메뉴 | 내 대시보드, 접근 가능한 관리 화면, 로그아웃 |
| 로그인 | 비로그인 사용자에게 로그인 버튼 표시 |

## 4. 목록 페이지 본문

`/docs`에서는 본문 컨테이너 전체를 문서 탐색과 목록에 사용한다.

```text
본문 컨테이너
├─ 좌측 탐색
│  ├─ 월드
│  ├─ 프로젝트
│  └─ 카테고리 트리
└─ 문서 목록
   ├─ 현재 탐색 범위
   ├─ 새 문서 작성
   ├─ 필터·정렬
   ├─ 목록
   └─ 페이지네이션
```

## 5. 전역 문서 탐색

```text
모든 문서
모든 월드와 프로젝트에 등록된 설정 문서를 탐색합니다.
```

다음 정보를 간단히 표시한다.

- 전체 월드 수
- 전체 프로젝트 수
- 전체 공개·사용 문서 수
- 현재 검색 조건의 문서 수

## 6. 좌측 탐색

카테고리는 프로젝트 소관이며 프로젝트마다 구조가 다르다. 월드와 프로젝트를 먼저 선택한 뒤 해당 프로젝트의 카테고리 트리를 표시한다.

```text
모든 문서

월드
├─ 월드 1
│  ├─ 프로젝트 1
│  └─ 프로젝트 2
└─ 월드 2
   └─ 프로젝트 3

선택한 프로젝트의 카테고리
├─ 인물
├─ 지역
└─ 사건
```

| 선택 범위 | 처리 |
|---|---|
| 아무것도 선택하지 않음 | 모든 문서 표시, 카테고리 트리 미표시 |
| 월드만 선택 | 해당 월드의 프로젝트 목록 표시 |
| 프로젝트 선택 | 해당 프로젝트의 카테고리 트리 표시 |
| 카테고리 선택 | 해당 카테고리 문서만 표시 |

서로 다른 프로젝트의 카테고리는 이름이 같더라도 하나로 합치지 않는다.

### 6.1 카테고리 트리 기능

- 1·2·3단계 카테고리 탐색
- 카테고리별 문서 수 표시
- 현재 선택 카테고리 강조
- 카테고리 접기·펼치기
- 모바일에서 드로어로 전환
- 사용 중이고 삭제되지 않은 카테고리만 노출

## 7. 필터 상태와 URL

```text
/docs?worldId=:worldId
/docs?worldId=:worldId&projectId=:projectId
/docs?worldId=:worldId&projectId=:projectId&categoryId=:categoryId
```

```text
월드 선택
└─ 프로젝트 선택
   └─ 카테고리 선택
      └─ 템플릿 선택
```

상위 선택을 변경하면 더 이상 유효하지 않은 하위 필터를 초기화한다.

## 8. 검색·필터·정렬

| 기능 | 내용 |
|---|---|
| 월드 | 전체 또는 특정 월드 |
| 프로젝트 | 선택한 월드의 프로젝트 |
| 카테고리 | 선택한 프로젝트의 카테고리 |
| 템플릿 | 선택한 프로젝트에서 사용하는 템플릿 |
| 검색 | 문서 제목과 검색 가능한 본문 |
| 정렬 | 제목·생성일·수정일 |
| 정렬 방향 | 오름차순·내림차순 |

기본 정렬은 최근 수정순으로 한다. 목록에는 사용 중이고 삭제되지 않은 문서만 표시한다.

## 9. 문서 목록

| 표시 항목 | 내용 |
|---|---|
| 문서 제목 | 문서 상세 이동 |
| 월드 | 문서가 속한 월드 |
| 프로젝트 | 문서가 속한 프로젝트 |
| 카테고리 | 프로젝트 내 카테고리 경로 |
| 템플릿 | 적용된 템플릿 |
| 요약 | 문서 본문 또는 설명 일부 |
| 관련 문서 수 | 연결된 문서 수 |
| 수정일 | 마지막 수정 날짜 |

월드와 프로젝트 정보를 제목 바로 아래에 고정적으로 표시한다.

## 10. 새 문서 작성

다음 조건을 모두 만족하는 관리자에게만 표시한다.

- 로그인 상태
- 계정 사용 상태
- 최초 비밀번호 변경 완료
- 문서 생성 권한을 가진 프로젝트가 하나 이상 존재
- 대상 월드와 프로젝트가 사용 상태

슈퍼 어드민에게는 항상 표시한다.

`/docs`에서 버튼을 선택하면 작성 권한이 있는 월드와 프로젝트를 고른 후 문서 생성 페이지로 이동한다. 현재 필터가 유효한 프로젝트를 가리키고 생성 권한이 있다면 선택 단계를 생략할 수 있다.

## 11. 상세 페이지 본문

`/docs/:documentId`에서는 같은 본문 컨테이너의 내부를 좌우로 나눈다.

```text
본문 컨테이너
├─ 좌측 주 콘텐츠
│  ├─ 탭
│  │  ├─ 설정 본문
│  │  └─ 향후 추가 탭
│  └─ 선택된 탭 콘텐츠
└─ 우측 보조 영역
   └─ 목차
```

목록 페이지와 상세 페이지는 레이아웃이 같고 본문 내부 구성만 다르다.

## 12. 설정 본문 탭

첫 번째 탭은 `설정 본문`으로 고정한다.

```text
설정 본문
├─ 상단: 메타데이터
└─ 하단: 문서 본문
```

### 12.1 메타데이터

템플릿에서 정의한 구조화 필드 값을 순서대로 표시한다.

- 값이 없는 필드는 기본적으로 숨김
- 문서 참조는 대상 문서 링크로 표시
- 다중 선택은 태그 형태로 표시
- 날짜·숫자·URL·이미지·파일은 필드 타입에 맞게 표현
- 구조화 필드가 많으면 논리적 그룹으로 구분

### 12.2 문서 본문

- 템플릿 섹션과 문서 전용 섹션을 문서 순서대로 렌더링
- 제목 단계에 따라 문서 구조 유지
- Markdown 렌더링
- 위키 링크를 실제 문서 링크로 변환
- 이미지·표·인용문·목록 지원
- 일반 뷰어에게는 사용 중인 최종 내용만 표시

## 13. 우측 목차

우측에는 현재 표시 중인 설정 본문의 목차를 배치한다.

- 메타데이터와 본문 섹션으로 이동
- 현재 읽고 있는 섹션 강조
- 항목 선택 시 해당 위치로 스크롤
- 긴 문서에서 상단 고정
- 모바일에서는 접을 수 있는 목차로 전환

두 번째 이후 탭이 추가될 때 목차가 탭별로 어떻게 동작할지는 추후 결정한다.

## 14. 확장 지점

다음 항목은 배치를 확정하지 않는다.

- 두 번째 이후 탭의 종류
- 관계 데이터를 독립 탭으로 표시할지 여부
- 관계 데이터를 우측 목차 아래에 표시할지 여부
- 관계 데이터 일부와 전체 화면을 나누어 표시할지 여부
- 관계 기반 표현 기능의 배치

현재 UI에는 미확정 탭이나 빈 관계 패널을 노출하지 않는다.

구현 구조만 다음 확장을 허용하도록 한다.

- 좌측 탭 목록을 데이터 기반으로 확장
- 첫 번째 설정 본문 탭만 우선 노출
- 우측 목차 아래에 보조 패널을 추가할 수 있는 구조 확보
- 관계 UI는 별도 확정 전까지 구현하지 않음

## 15. 문서 상태와 권한

| 상태 | 처리 |
|---|---|
| 정상 | 문서 전체 표시 |
| 미사용 | 일반 뷰어 접근 제한, 권한 있는 관리자에게 상태 안내 |
| 삭제 | 일반 뷰어 404, 권한 있는 관리자에게 삭제 상태와 복원 제공 |
| 프로젝트 미사용 | 일반 뷰어 접근 제한 |
| 월드 미사용 | 일반 뷰어 접근 제한 |
| 권한 없음 | 접근 제한 안내 |
| 존재하지 않음 | 404 화면 |

문서 수정·삭제·관계 추가 버튼은 해당 권한을 가진 관리자에게만 표시한다.

## 16. 프로젝트 문서 관리

프로젝트 레이아웃의 기존 메뉴와 경로를 사용한다.

```text
프로젝트 데이터
└─ 문서
   └─ /worlds/:worldId/projects/:projectId/documents
```

프로젝트 문서 관리에서는 생성·조회·수정·삭제·복원·상태 변경과 관계 조회·추가 기능을 제공한다.

## 17. 핵심 원칙

- `/docs`는 모든 문서를 탐색하는 기본 페이지다.
- `/`는 `/docs`로 리다이렉트한다.
- 목록과 상세는 동일한 문서 공통 레이아웃을 사용한다.
- 목록은 본문 컨테이너에 탐색과 목록을 표시한다.
- 상세는 본문 컨테이너 내부를 좌측 주 콘텐츠와 우측 목차로 나눈다.
- 상세 좌측 첫 번째 탭은 설정 본문이다.
- 설정 본문은 상단 메타데이터와 하단 문서 본문으로 나눈다.
- 관계 데이터의 탭·우측 영역 배치는 추후 결정한다.
- 문서 관리는 프로젝트 레이아웃에서 처리한다.
