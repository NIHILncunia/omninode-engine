# 옴니노드 대시보드 메뉴 설계

## 1. 목적

옴니노드 대시보드는 슈퍼 어드민이 사용하는 최상위 운영 콘솔이다.

슈퍼 어드민은 시스템에 존재하는 모든 월드, 프로젝트, 카테고리, 템플릿, 문서, 관계 유형, 관계와 관리자 데이터를 이 영역에서 직접 조회하고 관리한다.

일반 어드민과 서브 어드민이 자신의 월드 또는 프로젝트 대시보드에서 권한 범위에 따라 데이터를 관리하는 흐름과는 별개다.

## 2. 최종 계층

옴니노드의 최신 관리 계층은 다음과 같다.

```text
옴니노드
└─ 월드
   └─ 프로젝트
```

옴니노드 대시보드는 이 계층 전체를 관리한다.

## 3. 기본 경로

옴니노드 대시보드의 기본 경로는 `/omninode`로 한다.

모든 하위 데이터 관리 화면은 옴니노드 레이아웃 안에서 열린다. 슈퍼 어드민은 데이터를 수정하기 위해 월드 또는 프로젝트 대시보드로 이동할 필요가 없다.

## 4. 좌측 메뉴

```text
옴니노드
└─ 대시보드

전체 데이터
├─ 월드
├─ 프로젝트
├─ 카테고리
├─ 템플릿
├─ 문서
├─ 관계 유형
└─ 관계

기본 데이터
├─ 기본 카테고리
├─ 기본 템플릿
└─ 기본 관계 유형

관리자
├─ 어드민
└─ 어드민 승인
```

전체 데이터 메뉴에서는 메뉴명에 `모든`을 반복하지 않는다. 옴니노드 대시보드의 목록은 기본적으로 시스템 전체 범위를 의미하며, 화면 제목과 설명에서 전체 범위를 명시한다.

## 6. 공통 목록 구조

전체 데이터 화면은 동일한 조작 체계를 사용한다.

```text
화면 제목
├─ 전체 건수
├─ 데이터 생성 버튼
├─ 검색
├─ 필터
├─ 정렬
└─ 데이터 목록
   ├─ 상세 조회
   ├─ 수정
   ├─ 사용·미사용
   ├─ 삭제
   └─ 복원
```

### 6.1 공통 필터

- 사용 상태
- 삭제 상태
- 기본 데이터 여부
- 생성자
- 생성일
- 수정일

소속 범위가 있는 데이터에는 월드와 프로젝트 필터를 추가한다.

### 6.2 공통 관리 원칙

- 슈퍼 어드민은 옴니노드 대시보드 안에서 모든 일반 데이터를 생성·조회·수정·삭제·복원할 수 있다.
- 삭제 정책은 DB 명세의 소프트 삭제 정책을 따른다.
- 삭제된 데이터는 같은 목록에서 필터로 조회하고 복원할 수 있다.
- 기본 데이터에는 일반 데이터와 다른 변경 제한을 적용한다.
- 일반 어드민과 서브 어드민의 범위별 관리는 월드·프로젝트 대시보드에서 별도로 처리한다.

## 15. 기본 데이터

기본 데이터는 일반 사용자 데이터가 아니라 시스템 공통 코드 데이터로 취급한다.

전체 데이터 목록에도 포함되지만 기본 데이터 메뉴에서는 코드성 기본값만 집중적으로 관리한다.

### 15.1 공통 기능

- 기본 코드 등록
- 표시 이름과 설명 관리
- 사용·미사용 전환
- 적용 현황 조회
- 연결 가능한 범위 설정
- 기본 템플릿 필드 관리
- 기본 관계 유형 조건 관리

### 15.2 관리 제한

- DB에서 확정한 기본 데이터 변경 제한을 따른다.
- 일반 사용자 정의 데이터처럼 임의 삭제하지 않는다.
- 식별 코드의 안정성을 유지한다.
- 비활성화와 적용 현황 확인을 중심으로 관리한다.

## 17. 어드민 승인

일반 어드민 생성 요청을 처리한다.

### 17.1 목록 항목

| 항목 | 내용 |
|---|---|
| 요청자 | 승인을 요청한 관리자 |
| 대상자 | 생성될 일반 어드민 |
| 이메일 | 초대 이메일 |
| 요청 사유 | 관리 목적 |
| 요청일 | 승인 요청 날짜 |
| 상태 | 대기·승인·반려 |
| 처리자 | 승인·반려한 슈퍼 어드민 |
| 처리일 | 처리 날짜 |

### 17.2 주요 기능

- 승인 요청 상세 조회
- 일반 어드민 생성 승인
- 승인 반려
- 처리 이력 조회
- 승인 후 임시 비밀번호 발송 상태 확인
