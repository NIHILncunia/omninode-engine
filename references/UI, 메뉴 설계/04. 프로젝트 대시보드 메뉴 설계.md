# 프로젝트 대시보드 메뉴 설계

## 1. 목적

프로젝트 대시보드는 선택한 프로젝트의 카테고리, 템플릿, 문서와 관리자를 세부적으로 관리하는 공간이다.

관계 유형과 관계 대상 조건은 월드에서 정의한다. 프로젝트에서는 현재 프로젝트의 문서를 포함하고 월드에서 설정한 대상 조건을 만족하는 실제 관계를 생성하고 관리한다.

## 2. 기본 경로

프로젝트 대시보드의 기본 경로는 `/worlds/:worldId/projects/:projectId`로 한다.

## 3. 좌측 메뉴

```text
프로젝트
├─ 대시보드
└─ 프로젝트 정보

프로젝트 데이터
├─ 카테고리
├─ 템플릿
└─ 문서

관계
├─ 사용 가능한 관계 유형
└─ 관련 관계

관리자
└─ 어드민
```

## 4. 메뉴와 콘텐츠 매핑

| 메뉴 그룹 | 좌측 메뉴 | 경로 | 관리 수준 |
|---|---|---|---|
| 프로젝트 | 대시보드 | `/worlds/:worldId/projects/:projectId` | 프로젝트 전체 현황 조회 |
| 프로젝트 | 프로젝트 정보 | `/worlds/:worldId/projects/:projectId/settings` | 프로젝트 정보 직접 관리 |
| 프로젝트 데이터 | 카테고리 | `/worlds/:worldId/projects/:projectId/categories` | 기본 카테고리 연결 및 사용자 정의 카테고리 관리 |
| 프로젝트 데이터 | 템플릿 | `/worlds/:worldId/projects/:projectId/templates` | 기본 템플릿 연결 및 사용자 정의 템플릿 관리 |
| 프로젝트 데이터 | 문서 | `/worlds/:worldId/projects/:projectId/documents` | 프로젝트 문서 직접 관리 |
| 관계 | 사용 가능한 관계 유형 | `/worlds/:worldId/projects/:projectId/relation-types` | 월드 관계 유형과 대상 조건 조회 |
| 관계 | 관련 관계 | `/worlds/:worldId/projects/:projectId/relations` | 현재 프로젝트 문서를 포함한 실제 관계 관리 |
| 관리자 | 어드민 | `/worlds/:worldId/projects/:projectId/admins` | 프로젝트 관리자와 세부 권한 관리 |

## 5. 대시보드

### 5.1 프로젝트 요약

| 카드 | 내용 |
|---|---|
| 카테고리 | 기본·사용자 정의 카테고리 수 |
| 템플릿 | 기본·사용자 정의 템플릿 수 |
| 문서 | 전체·사용·삭제 문서 수 |
| 관계 | 프로젝트 문서가 포함된 관계 수 |
| 관계 유형 | 현재 프로젝트에서 사용할 수 있는 관계 유형 수 |
| 어드민 | 프로젝트 관리 권한을 가진 관리자 수 |

### 5.2 카테고리 현황

| 컬럼 | 내용 |
|---|---|
| 카테고리명 | 1단계 카테고리 이름 |
| 하위 카테고리 수 | 2·3단계 카테고리 수 |
| 템플릿 수 | 연결된 템플릿 수 |
| 문서 수 | 해당 트리에 속한 문서 수 |
| 상태 | 사용 여부 |

### 5.3 최근 작업

- 최근 생성·수정된 문서
- 최근 생성된 사용자 정의 카테고리
- 최근 생성·수정된 템플릿
- 최근 생성된 관계
- 최근 추가된 어드민

최근 데이터는 현재 프로젝트 범위로 제한한다.

## 6. 프로젝트 정보

| 항목 | 처리 |
|---|---|
| 프로젝트명 | 수정 가능 |
| 프로젝트 설명 | 수정 가능 |
| 소속 월드 | 조회만 가능 |
| 사용 상태 | 권한에 따라 변경 |
| 생성자 | 조회만 가능 |
| 생성일 | 조회만 가능 |
| 수정자 | 조회만 가능 |
| 수정일 | 조회만 가능 |
| 삭제 상태 | 조회 및 복원 가능 |

### 6.1 주요 기능

- 프로젝트 이름·설명 수정
- 사용·미사용 전환
- 프로젝트 삭제
- 삭제된 프로젝트 복원
- 소속 월드 대시보드 이동

프로젝트 소속 월드 변경은 슈퍼 어드민의 옴니노드 대시보드에서만 허용한다.

## 7. 카테고리

현재 프로젝트에서 사용하는 기본 카테고리와 사용자 정의 카테고리를 함께 관리한다.

### 7.1 카테고리 트리

```text
카테고리
├─ 1단계
│  ├─ 2단계
│  │  └─ 3단계
│  └─ 2단계
└─ 1단계
```

카테고리 화면 내부에는 대시보드 전체 메뉴와 별도로 카테고리 탐색용 트리를 둔다.

### 7.2 목록 컬럼

| 컬럼 | 내용 |
|---|---|
| 카테고리명 | 카테고리 이름 |
| 구분 | 기본 또는 사용자 정의 |
| 상위 카테고리 | 상위 카테고리 |
| 단계 | 1·2·3단계 |
| 템플릿 수 | 연결된 템플릿 수 |
| 문서 수 | 소속 문서 수 |
| 정렬 순서 | 같은 단계 안의 표시 순서 |
| 상태 | 사용·미사용·삭제 |

### 7.3 기본 카테고리

- 사용 가능한 기본 카테고리 조회
- 프로젝트에 기본 카테고리 연결
- 프로젝트 내 사용·미사용 전환
- 프로젝트 연결 해제
- 계층과 정의 조회
- 기본 정의 자체의 수정·삭제 불가

### 7.4 사용자 정의 카테고리

- 생성
- 상세 조회
- 수정
- 삭제·복원
- 상위 카테고리 설정
- 정렬 순서 변경
- 사용·미사용 전환

카테고리 단계는 최대 3단계이며 역방향 계층은 허용하지 않는다.

## 8. 템플릿

현재 프로젝트에서 사용하는 기본 템플릿과 사용자 정의 템플릿을 관리한다.

### 8.1 목록 컬럼

| 컬럼 | 내용 |
|---|---|
| 템플릿명 | 템플릿 이름 |
| 구분 | 기본 또는 사용자 정의 |
| 연결 카테고리 | 템플릿이 연결된 1단계 카테고리 |
| 필드 수 | 템플릿 필드 수 |
| 문서 수 | 템플릿을 사용하는 문서 수 |
| 상태 | 사용·미사용·삭제 |
| 수정일 | 마지막 수정 날짜 |

### 8.2 기본 템플릿

- 사용 가능한 기본 템플릿 조회
- 프로젝트 카테고리에 연결
- 프로젝트 내 사용·미사용 전환
- 프로젝트 연결 해제
- 필드 구조 조회
- 기본 정의와 필드 수정·삭제 불가

### 8.3 사용자 정의 템플릿

- 생성
- 상세 조회
- 수정
- 삭제·복원
- 1단계 카테고리 연결
- 필드 생성·수정·삭제
- 필드 순서 변경
- 선택형 필드의 선택지 관리
- 사용·미사용 전환

템플릿은 1단계 카테고리에만 연결한다.

## 9. 문서

현재 프로젝트의 설정 문서를 직접 관리한다.

### 9.1 목록 컬럼

| 컬럼 | 내용 |
|---|---|
| 문서 제목 | 문서 제목 |
| 카테고리 | 문서 카테고리 |
| 템플릿 | 적용 템플릿 |
| 관계 수 | 연결된 관계 수 |
| 생성자 | 문서 생성 관리자 |
| 상태 | 사용·미사용·삭제 |
| 생성일 | 생성 날짜 |
| 수정일 | 마지막 수정 날짜 |

### 9.2 필터와 검색

- 카테고리 트리
- 템플릿
- 생성자
- 사용 상태
- 삭제 상태
- 문서 제목
- 생성일·수정일

### 9.3 주요 기능

- 문서 생성
- 문서 상세 열기
- 문서 수정
- 문서 삭제·복원
- 사용·미사용 전환
- 연결된 관계 조회
- 관계 추가

문서 상세, 생성, 수정은 각각의 전용 레이아웃으로 연다. 프로젝트 대시보드의 문서 메뉴는 문서 목록과 관리 진입점 역할을 한다.

## 10. 사용 가능한 관계 유형

현재 프로젝트의 카테고리가 관계 대상 조건에 포함된 관계 유형만 보여준다.

### 10.1 목록 컬럼

| 컬럼 | 내용 |
|---|---|
| 관계 유형명 | 관계 이름 |
| 구분 | 기본 또는 사용자 정의 |
| 대상 수 | 최소·최대 대상 수 |
| 현재 프로젝트 대상 | 현재 프로젝트에서 허용된 카테고리 |
| 연결 대상 | 연결 가능한 다른 프로젝트와 카테고리 |
| 방향성 | 단방향 또는 양방향 |
| 사용 관계 수 | 현재 프로젝트와 관련된 관계 수 |
| 상태 | 사용 가능 여부 |

### 10.2 상세 콘텐츠

- 관계 유형 기본 정보
- 대상별 역할
- 대상 순서
- 필수 여부
- 대상별 허용 프로젝트
- 대상별 허용 카테고리
- 현재 프로젝트가 참여할 수 있는 대상 위치
- 해당 유형으로 생성된 관련 관계

프로젝트 대시보드에서는 관계 유형과 대상 조건을 수정하지 않는다.

## 11. 관련 관계

현재 프로젝트의 문서가 하나 이상 참여한 실제 관계만 표시한다.

### 11.1 목록 컬럼

| 컬럼 | 내용 |
|---|---|
| 관계 유형 | 적용된 관계 유형 |
| 현재 프로젝트 문서 | 현재 프로젝트에서 참여한 문서 |
| 연결 문서 | 다른 대상 문서 |
| 연결 프로젝트 | 연결 문서가 속한 프로젝트 |
| 연결 카테고리 | 연결 문서의 카테고리 |
| 대상 수 | 관계에 참여한 문서 수 |
| 생성자 | 관계 생성 관리자 |
| 상태 | 사용·미사용·삭제 |
| 생성일·수정일 | 관리 날짜 |

### 11.2 관계 생성 흐름

1. 현재 프로젝트의 기준 문서를 선택한다.
2. 기준 문서가 참여할 수 있는 관계 유형만 표시한다.
3. 기준 문서가 들어갈 수 있는 대상 위치를 판정한다.
4. 나머지 대상의 프로젝트·카테고리 조건을 적용한다.
5. 조건에 맞는 문서만 선택 후보로 표시한다.
6. 대상 문서를 선택하고 관계를 저장한다.

현재 프로젝트의 문서가 관계 대상 중 하나로 반드시 포함되어야 한다.

### 11.3 주요 기능

- 관계 생성
- 관계 상세 조회
- 권한이 있는 관계 수정
- 권한이 있는 관계 삭제·복원
- 관계 참여 문서 상세 열기
- 관계 유형과 대상 조건 조회

관계 생성 폼은 프로젝트 관계 목록과 문서 화면에서 공통으로 사용한다. 문서 화면에서 진입하면 현재 문서를 자동으로 대상 하나에 지정한다.

## 12. 어드민

현재 프로젝트에 관리 권한이 있는 관리자만 표시한다.

### 12.1 목록 컬럼

| 컬럼 | 내용 |
|---|---|
| 이름 | 관리자 이름 |
| 이메일 | 관리자 이메일 |
| 역할 | 일반 어드민 또는 서브 어드민 |
| 권한 | 프로젝트에서 부여된 권한 |
| 계정 상태 | 사용·정지·삭제 |
| 초대 상태 | 발송·수락·만료 |
| 마지막 로그인 | 마지막 로그인 날짜 |

### 12.2 주요 기능

- 프로젝트 관리자 조회
- 월드에 존재하는 서브 어드민 연결
- 서브 어드민 생성·초대
- 초대 재발송
- 프로젝트 세부 권한 설정
- 권한 수정·회수
- 프로젝트에서 관리자 제외

새 서브 어드민을 프로젝트에서 초대하면 현재 월드의 서브 어드민으로 생성하고 현재 프로젝트 권한을 함께 부여한다.

## 13. 권한 적용

| 권한 | UI 처리 |
|---|---|
| 조회 | 메뉴와 목록 접근 |
| 생성 | 생성 버튼 노출 |
| 수정 | 수정과 상태 변경 버튼 노출 |
| 삭제 | 삭제와 복원 버튼 노출 |
| 서브 어드민 초대 | 초대 버튼 노출 |
| 권한 관리 | 프로젝트 권한 설정 기능 노출 |

슈퍼 어드민은 모든 작업이 가능하다. 일반 어드민과 서브 어드민은 프로젝트별 권한 매핑을 기준으로 메뉴와 버튼을 노출한다.

## 14. 관계 구조

```text
월드
├─ 프로젝트 1
│  └─ 카테고리 A
│     └─ 문서 1
├─ 프로젝트 2
│  └─ 카테고리 B
│     └─ 문서 2
├─ 관계 유형
│  └─ 관계 대상 설정
│     ├─ 대상 1: 프로젝트 1 · 카테고리 A
│     └─ 대상 2: 프로젝트 2 · 카테고리 B
└─ 실제 관계
   ├─ 대상 1: 문서 1
   └─ 대상 2: 문서 2
```

서로 다른 프로젝트의 문서도 같은 월드에 속하고 관계 대상 조건을 만족하면 연결할 수 있다.
