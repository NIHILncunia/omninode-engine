# 문서 생성·수정 공통 편집 레이아웃 설계

## 1. 목적

문서 생성과 수정은 동일한 문서 편집 레이아웃과 동일한 폼 컴포넌트를 사용한다.

두 모드의 차이는 기존 문서 ID와 초기값의 존재 여부, 저장 시 수행하는 작업이다.

## 2. 경로

| 모드 | 경로 |
|---|---|
| 문서 생성 | `/docs/create?worldId=:worldId&projectId=:projectId` |
| 문서 수정 | `/docs/:documentId/edit` |

어느 대시보드나 문서 상세에서 진입하더라도 같은 편집 레이아웃으로 이동한다.

## 3. 공통 구조

```text
상단 작업 영역
├─ 옴니노드 로고
├─ 생성·수정 모드 표시
├─ 문서 소속 정보
└─ 취소·저장

편집 본문
├─ 좌측 편집 영역
│  ├─ 기본 정보
│  ├─ 메타데이터
│  └─ 문서 본문
└─ 우측 보조 영역
   ├─ 편집 목차
   ├─ 입력 상태
   └─ 검증 오류
```

## 4. 생성·수정 모드 차이

| 항목 | 생성 | 수정 |
|---|---|---|
| 문서 ID | 없음 | 기존 ID |
| 월드 | 전달값 또는 권한 범위에서 선택 | 읽기 전용 |
| 프로젝트 | 전달값 또는 권한 범위에서 선택 | 읽기 전용 |
| 제목 | 입력 가능 | 읽기 전용 |
| 카테고리 | 선택 가능 | 읽기 전용 |
| 템플릿 | 카테고리에 따라 자동 지정 | 읽기 전용 |
| 메타데이터 | 빈 초기값 | 현재 리비전 값 |
| 본문 | 템플릿 기준 빈 섹션 | 현재 리비전 내용 |
| 저장 | 문서와 첫 리비전 생성 | 새 현재 리비전 생성 |

## 5. 문서 정체성

최초 저장할 때 다음 항목을 문서의 정체성으로 확정한다.

```text
문서 정체성
├─ 제목
├─ 프로젝트
├─ 카테고리
└─ 템플릿
```

저장된 문서의 수정 화면에서는 네 항목을 읽기 전용으로 표시한다.

다른 제목이나 카테고리의 문서가 필요하면 새 문서를 작성한다.

## 6. 상단 작업 영역

| 영역 | 내용 |
|---|---|
| 로고 | 옴니노드 문서 목록 이동 |
| 모드 | 새 문서 작성 또는 문서 수정 |
| 월드 | 문서가 속할 월드 |
| 프로젝트 | 문서가 속할 프로젝트 |
| 취소 | 이전 화면으로 이동 |
| 저장 | 문서 생성 또는 새 리비전 저장 |

상단 작업 영역은 긴 문서를 편집할 때도 접근할 수 있도록 고정할 수 있다.

## 7. 기본 정보

### 7.1 생성 모드

```text
월드
프로젝트
문서 제목
카테고리
자동 지정 템플릿
```

### 7.2 선택 순서

1. 월드를 확정한다.
2. 해당 월드에서 생성 권한이 있는 프로젝트를 확정한다.
3. 프로젝트에서 사용 중인 카테고리를 선택한다.
4. 선택한 카테고리에 연결된 템플릿을 자동으로 지정한다.
5. 템플릿에 따라 메타데이터와 본문 입력 폼을 생성한다.

### 7.3 수정 모드

월드, 프로젝트, 제목, 카테고리와 템플릿을 읽기 전용 정보로 표시한다.

## 8. 생성 중 카테고리 변경

최초 저장 전에는 카테고리를 변경할 수 있다.

아직 입력한 메타데이터와 본문이 없다면 즉시 새 템플릿 폼으로 교체한다.

입력한 내용이 있다면 다음 경고를 표시한다.

```text
카테고리를 변경하시겠습니까?

카테고리를 변경하면 현재 입력한 메타데이터와 본문이
모두 초기화되고 새 템플릿 입력 폼으로 교체됩니다.

[취소] [카테고리 변경]
```

저장된 문서의 수정 화면에는 카테고리 변경 기능을 제공하지 않는다.

## 9. 메타데이터 편집

선택된 템플릿의 구조화 필드를 순서대로 렌더링한다.

| 필드 유형 | 입력 UI |
|---|---|
| 단문 텍스트 | 텍스트 입력 |
| 장문 텍스트 | 텍스트 영역 |
| 숫자 | 숫자 입력 |
| 날짜 | 날짜 입력 |
| 참·거짓 | 스위치 또는 라디오 |
| 단일 선택 | 셀렉트 |
| 다중 선택 | 다중 셀렉트 |
| 이미지 | 이미지 업로드 |
| 파일 | 파일 업로드 |
| URL | URL 입력 |
| 문서 참조 | 문서 검색·선택 |
| 관계형 필드 | 관계 UI 확정 후 결정 |

각 필드에는 필드명, 설명, 필수 여부, 입력 예시와 검증 오류를 표시한다. 필드 순서와 그룹은 템플릿 정의를 따른다.

## 10. 문서 본문 편집

본문은 템플릿 섹션과 문서 전용 섹션을 분할하여 편집한다.

```text
문서 본문
├─ 개요
├─ 외형
├─ 성격
└─ 생애
```

| 항목 | 내용 |
|---|---|
| 섹션 제목 | 템플릿 또는 문서 전용 제목 |
| 제목 단계 | `#`, `##`, `###` |
| 본문 | Markdown 편집 |
| 순서 | 현재 문서 안의 표시 순서 |
| 출처 | 템플릿 또는 문서 전용 |

### 10.1 템플릿 섹션

- 섹션 제목과 단계는 템플릿 정의를 따름
- 문서에서 임의로 승격하지 않음
- 내용만 작성
- 삭제된 템플릿 섹션은 관리자에게 경고

### 10.2 문서 전용 섹션

- 문서에 필요한 추가 섹션 생성
- 제목과 제목 단계 설정
- 내용 작성
- 순서 변경
- 삭제 가능
- 템플릿 섹션으로 승격 불가

## 11. 우측 편집 목차

```text
편집 목차
├─ 기본 정보
├─ 메타데이터
├─ 개요
├─ 외형
├─ 성격
└─ 생애
```

- 항목 선택 시 해당 입력 영역으로 이동
- 현재 편집 중인 영역 강조
- 필수 입력 누락 표시
- 검증 오류가 있는 섹션 표시
- 긴 문서에서 상단 고정
- 모바일에서는 드로어 또는 접이식 목차로 전환

## 12. 저장

### 12.1 생성 모드

다음 데이터를 한 번에 저장한다.

- 문서 기본 정보
- 프로젝트·카테고리·템플릿 연결
- 첫 번째 리비전
- 메타데이터 값
- 템플릿 섹션 본문
- 문서 전용 섹션

저장 성공 후 생성된 문서 상세로 이동한다.

### 12.2 수정 모드

수정된 내용을 새로운 현재 리비전으로 저장한다.

자동 저장은 사용하지 않는다. 사용자가 저장 버튼을 선택했을 때만 새 리비전을 생성한다.

저장 성공 후 문서 상세로 이동한다.

## 13. 취소와 이탈 방지

변경된 값이 없으면 즉시 이전 화면으로 이동한다.

저장하지 않은 변경이 있으면 다음 경고를 표시한다.

```text
저장하지 않은 변경사항이 있습니다.

페이지를 나가면 작성한 내용이 사라집니다.

[계속 작성] [저장하지 않고 나가기]
```

브라우저 뒤로 가기, 내부 링크 이동과 새로고침에도 동일한 이탈 방지 정책을 적용한다.

## 14. 검증

| 검증 대상 | 내용 |
|---|---|
| 제목 | 필수, 제목 정책과 중복 검사 |
| 월드 | 접근·사용 상태 |
| 프로젝트 | 생성 권한과 사용 상태 |
| 카테고리 | 프로젝트 연결과 사용 상태 |
| 템플릿 | 카테고리 연결과 사용 상태 |
| 메타데이터 | 필수값과 필드 타입 |
| 본문 | 섹션 구조와 입력 제한 |
| 파일 | 형식과 크기 |
| 문서 참조 | 접근 가능하고 유효한 문서 |

검증 오류가 있으면 저장하지 않고 해당 필드와 우측 목차에 오류를 표시한다.

## 15. 권한

### 15.1 생성 모드

- 문서 생성 권한 필요
- 권한이 있는 월드·프로젝트만 선택 가능
- 사용 중인 카테고리·템플릿만 선택 가능

### 15.2 수정 모드

- 해당 프로젝트의 문서 수정 권한 필요
- 권한이 없으면 문서 상세로 이동
- 삭제되거나 미사용인 문서는 권한 정책에 따라 수정 제한
- 슈퍼 어드민은 항상 접근 가능

## 16. 관계 데이터

다음 항목은 관계 UI를 설계할 때 별도로 결정한다.

- 관계형 필드의 UI
- 편집 화면 안의 관계 탭
- 저장과 관계 생성의 결합 여부
- 기존 관계 표시 위치

현재 문서 편집은 메타데이터와 설정 본문 저장에 집중한다.

## 17. 핵심 원칙

- 문서 생성과 수정은 동일한 편집 레이아웃을 사용한다.
- 생성과 수정의 차이는 초기값과 저장 작업이다.
- 최초 저장 이후 제목·프로젝트·카테고리·템플릿은 변경할 수 없다.
- 생성 중 카테고리 변경으로 작성 내용이 초기화되면 경고한다.
- 수정 저장은 기존 내용을 덮어쓰지 않고 새 현재 리비전을 생성한다.
- 자동 저장은 사용하지 않는다.
