# 옴니노드 UI 페이지 설계 설명서

## 1. 옴니노드 대시보드 — 슈퍼 어드민

### 목적

옴니노드 전체 시스템을 관리하는 슈퍼 어드민 전용 최상위 대시보드입니다.

모든 프로젝트와 월드를 관리할 수 있으며, 전체 시스템의 프로젝트·월드·문서·관리자 현황을 한 화면에서 파악할 수 있어야 합니다.

### 주요 정보

상단에는 다음과 같은 전체 시스템 KPI를 배치합니다.

* 전체 프로젝트 수
* 전체 월드 수
* 전체 문서 수
* 전체 관리자 수

KPI는 시스템 규모를 빠르게 파악하기 위한 보조 정보이며, 대시보드의 핵심은 실제 관리 작업과 최근 문서 확인입니다.

### 프로젝트 관리

슈퍼 어드민은 모든 프로젝트에 접근할 수 있습니다.

프로젝트 영역에서는 다음 정보를 확인할 수 있습니다.

* 프로젝트명
* 생성일
* 담당 관리자
* 포함 월드 수
* 프로젝트 상태
* 관리 메뉴

프로젝트 생성·조회·수정·삭제로 연결되는 관리 진입점도 제공합니다.

### 월드 관리

전체 프로젝트에 속한 월드를 프로젝트 구분과 함께 확인합니다.

주요 정보는 다음과 같습니다.

* 월드명
* 소속 프로젝트
* 문서 수
* 상태
* 관리 액션

특정 프로젝트를 먼저 선택하지 않아도 시스템 전체 월드를 확인할 수 있어야 합니다.

### 최근 문서

모든 프로젝트와 모든 월드에 존재하는 문서를 최근 수정순으로 통합하여 보여줍니다.

주요 표시 항목은 다음과 같습니다.

* 문서명
* 프로젝트
* 월드
* 카테고리
* 최근 수정일
* 상태
* 작성자 또는 수정자

다른 관리자가 문서를 숨김 처리한 경우에도 **문서가 존재한다는 사실과 목록 행 자체는 슈퍼 어드민에게 표시**합니다.

단, 숨김 문서는 다음과 같이 민감 정보를 표시하지 않습니다.

* 문서명: 비공개 또는 숨김 문서와 같은 대체 표현
* 카테고리: 비공개
* 내용 및 요약: 표시하지 않음

숨김 상태라는 사실은 명확한 상태 Badge 등으로 표현합니다.

### 최근 활동

최근 시스템 관리 활동을 간략히 확인할 수 있습니다.

예:

* 프로젝트 생성
* 월드 생성
* 문서 생성·수정
* 문서 숨김 처리
* 관리자 추가 또는 변경

감사 로그 전체를 대시보드에서 제공하는 것이 아니라 최근 주요 이벤트를 확인하는 용도입니다.

## 2. 문서 목록

### 목적

현재 접근 범위 안에 존재하는 설정 문서를 검색하고 탐색하는 기본 문서 관리 화면입니다.

위키의 문서 인덱스이면서 관리자가 문서를 빠르게 찾아 작업하기 위한 목록 화면입니다.

### 범위

접근 위치에 따라 목록 범위가 달라질 수 있습니다.

예:

* 슈퍼 어드민: 전체 시스템 문서
* 프로젝트: 프로젝트 내 모든 월드의 문서
* 월드: 해당 월드의 문서
* 카테고리: 해당 카테고리에 매핑된 문서

현재 범위는 상단 Context Selector 또는 Breadcrumb 등을 통해 명확하게 표시해야 합니다.

### 검색 및 필터

문서 수가 많아지는 것을 전제로 다음 기능을 제공합니다.

* 제목 검색
* 카테고리 필터
* 템플릿 필터
* 월드 필터
* 상태 필터
* 최근 수정순 등의 정렬

현재 페이지 범위에서 의미가 없는 필터는 노출하지 않아도 됩니다.

### 문서 테이블

문서 목록은 기본적으로 정보 밀도가 높은 테이블 형태를 사용합니다.

주요 컬럼은 다음과 같습니다.

* 즐겨찾기
* 제목
* 카테고리
* 템플릿
* 월드
* 최근 수정
* 상태
* 작성자 또는 수정자
* 추가 작업 메뉴

문서 제목이 가장 높은 시각적 우선순위를 가집니다.

### 상태

문서 상태는 Badge 등으로 명확히 구분합니다.

예:

* 공개
* 비공개
* 숨김
* 초안
* 삭제 예정 또는 삭제 상태

상태의 의미를 색상만으로 전달하지 않고 텍스트를 병행합니다.

### 보조 기능

필요에 따라 다음 기능을 제공합니다.

* 새 문서 생성
* 선택 문서 일괄 작업
* 즐겨찾기
* 최근 문서 바로가기
* 저장된 검색 또는 보기

## 3. 문서 상세 페이지

### 목적

설정 문서를 읽는 옴니노드의 기본 위키 화면입니다.

관리 기능보다 문서 콘텐츠 자체를 가장 높은 우선순위로 배치합니다.

### 본문 구조

본문은 Markdown 문서를 읽기 좋은 형태로 렌더링합니다.

주요 요소는 다음과 같습니다.

* 문서 제목
* Breadcrumb
* 기본 메타 정보
* 문서 본문
* 문서 내 Heading 구조
* 관련 문서
* 태그 또는 기타 분류 정보

본문은 화면 전체 폭을 사용하기보다는 읽기 좋은 최대 너비를 유지합니다.

### 문서 메타 정보

제목 아래 또는 우측 보조 패널에서 다음 정보를 제공합니다.

* 작성자
* 최종 수정자
* 최종 수정일
* 현재 버전
* 공개 상태
* 조회수
* 즐겨찾기 여부

메타 정보는 본문보다 시각적으로 낮은 우선순위를 가집니다.

### 좌측 탐색

현재 문서가 어느 위치에 있는지 이해할 수 있도록 프로젝트·월드·카테고리 계층 또는 문서 탐색 구조를 제공합니다.

현재 선택된 문서는 명확하게 강조합니다.

### 우측 정보 패널

필요할 경우 다음 정보를 우측 패널에 배치합니다.

* 문서 정보
* 태그
* 관련 문서
* 문서 히스토리 진입
* 빠른 링크

향후 문서 관계 기능도 이 영역과 자연스럽게 연결될 수 있습니다.

### 로그인 상태

비로그인 사용자에게는 상단에 **관리자 로그인 버튼**을 표시합니다.

관리자가 로그인한 경우에는 버튼 대신 관리자 정보 영역을 표시합니다.

로그인 상태에 따라 문서 내용 자체의 레이아웃이 크게 흔들리지 않도록 합니다.

## 4. 프로젝트 관리 대시보드

### 목적

하나의 프로젝트에 포함된 모든 월드와 문서, 카테고리, 템플릿의 상태를 확인하고 프로젝트 단위 관리 작업을 수행하는 대시보드입니다.

### 프로젝트 기본 정보

상단에서 현재 프로젝트 정보를 명확하게 보여줍니다.

예:

* 프로젝트명
* 프로젝트 설명
* 생성일
* 프로젝트 관리자 수
* 활성 상태
* 프로젝트 설정 진입

### 핵심 지표

프로젝트 전체 기준으로 다음 수치를 제공합니다.

* 월드 수
* 문서 수
* 템플릿 수
* 카테고리 수
* 최근 일정 기간의 수정 건수

각 지표는 가능하면 해당 관리 페이지로 이동할 수 있는 진입점 역할도 합니다.

### 월드 목록

프로젝트에 속한 모든 월드를 요약해서 보여줍니다.

주요 정보:

* 월드명
* 문서 수
* 최근 수정일
* 상태
* 작업 메뉴

월드를 생성하거나 상세 관리 화면으로 이동할 수 있습니다.

### 최근 문서

프로젝트에 속한 **모든 월드의 문서를 합쳐 최근 수정순으로 표시**합니다.

월드 구분을 반드시 함께 표시하여 문서가 어느 월드에 속하는지 즉시 확인할 수 있도록 합니다.

### 빠른 작업

자주 사용하는 프로젝트 작업을 별도 영역으로 제공할 수 있습니다.

예:

* 월드 생성
* 프로젝트 설정
* 관리자 관리 또는 초대

### 최근 활동

프로젝트 범위에서 발생한 최근 작업을 요약합니다.

시스템 전체 활동이 아니라 현재 프로젝트에 관련된 활동만 표시합니다.

## 5. 월드 관리 대시보드

### 목적

옴니노드에서 실질적으로 가장 자주 사용하는 관리 허브입니다.

설정 문서가 실제로 관리되는 단위가 월드이므로 문서·카테고리·템플릿을 한 화면에서 빠르게 파악하고 해당 기능으로 이동할 수 있어야 합니다.

### 월드 기본 정보

상단에는 현재 월드의 기본 정보를 제공합니다.

예:

* 월드명
* 소속 프로젝트
* 공개 또는 사용 상태
* 최근 업데이트
* 월드 설정

현재 프로젝트와 현재 월드의 Context가 명확하게 드러나야 합니다.

### 핵심 지표

월드 기준으로 다음 정보를 표시합니다.

* 문서 수
* 카테고리 수
* 템플릿 수
* 최근 수정 건수

월드 수는 프로젝트 대시보드에서 의미가 있으므로 월드 대시보드에는 포함하지 않습니다.

### 최근 문서

현재 월드의 문서를 최근 수정순으로 보여줍니다.

주요 정보:

* 문서명
* 카테고리
* 상태
* 최종 수정일
* 수정자

월드 대시보드에서 가장 중요한 콘텐츠 영역 중 하나입니다.

### 카테고리 관리 요약

현재 월드의 카테고리 구조를 요약해 보여줍니다.

예:

* 전체 카테고리 수
* 최상위 카테고리 수
* 주요 카테고리별 문서 수
* 카테고리 관리 페이지 바로가기

대시보드 안에서 모든 카테고리를 편집하는 것이 아니라 현황 확인과 관리 페이지 진입을 목적으로 합니다.

### 템플릿 관리 요약

현재 월드에서 사용 중인 템플릿 현황을 보여줍니다.

예:

* 전체 템플릿 수
* 사용 중인 템플릿 수
* 최근 수정된 템플릿
* 템플릿 관리 페이지 바로가기

### 빠른 액션

월드에서 가장 자주 수행할 작업을 제공합니다.

예:

* 새 문서 작성
* 카테고리 추가
* 템플릿 생성

이 영역은 실제 사용 빈도가 높은 작업만 포함하고 지나치게 많은 바로가기를 배치하지 않습니다.

### 최근 활동

현재 월드 내부에서 발생한 최근 편집과 구조 변경을 요약합니다.

## 6. 카테고리 관리 페이지

### 목적

월드 내 문서 분류 체계를 구성하는 카테고리를 생성·수정·삭제하고 계층 구조를 관리하는 페이지입니다.

### 카테고리 구조

카테고리는 최대 3단계 계층을 가질 수 있습니다.

예:

```text
인물
└─ 인간
   └─ 왕족
```

트리 UI를 사용하여 부모·자식 관계를 즉시 파악할 수 있어야 합니다.

### 좌측 카테고리 트리

다음 기능을 제공합니다.

* 카테고리 펼치기/접기
* 현재 선택 항목 강조
* 검색
* 카테고리 추가
* 하위 카테고리 추가
* 정렬 또는 순서 변경
* 항목별 추가 작업 메뉴

트리에서 현재 계층 깊이가 쉽게 구분되어야 합니다.

### 우측 상세 편집

선택한 카테고리의 상세 정보를 수정합니다.

주요 항목:

* 이름
* 상위 카테고리
* 설명
* 연결 템플릿
* 문서 수
* 활성 또는 사용 상태
* 정렬 순서

최상위 카테고리와 하위 카테고리에서 사용할 수 없는 항목이 있다면 UI에서 명확하게 구분합니다.

### 템플릿 연결

카테고리에 연결된 템플릿을 확인할 수 있습니다.

템플릿 적용 규칙은 실제 도메인 규칙을 따르며, UI가 별도의 새로운 규칙을 만들지 않습니다.

### 연결 문서

선택한 카테고리에 속한 최근 문서를 보조적으로 확인할 수 있습니다.

카테고리 관리의 중심 기능은 아니므로 상세 문서 탐색은 별도 문서 목록으로 연결합니다.

## 7. 템플릿 관리 페이지

### 목적

월드에서 사용하는 문서 템플릿과 Markdown 섹션 구조를 생성·편집·관리하는 페이지입니다.

템플릿은 문서 작성 시 어떤 Heading 구조를 기본으로 제공할지 결정합니다.

### 템플릿 목록

좌측 또는 별도 목록 영역에서 현재 월드의 템플릿을 확인합니다.

주요 정보:

* 템플릿명
* 연결 카테고리
* 사용 중인 문서 수
* 사용 상태
* 버전

검색과 새 템플릿 생성 기능을 제공합니다.

### 기본 정보

선택한 템플릿의 기본 정보를 확인하고 수정합니다.

예:

* 템플릿명
* 설명
* 버전
* 사용 상태
* 연결 카테고리

### 섹션 구조

템플릿의 가장 중요한 편집 영역입니다.

문서 Heading 구조를 다음 단계로 관리합니다.

* H1
* H2
* H3

각 섹션은 계층 관계와 표시 순서를 가져야 합니다.

### 섹션 관리

다음 기능을 고려합니다.

* 섹션 추가
* 섹션 삭제
* 섹션명 변경
* Heading Level 설정
* 순서 변경
* Drag & Drop
* 필수 여부 등 기존 설계에 정의된 옵션

섹션 구조는 실제 문서 작성 화면의 기본 구조로 사용됩니다.

### 문서 미리보기

현재 템플릿이 실제 문서에 적용될 경우 어떤 Heading 구조로 표현되는지 우측 미리보기에서 확인합니다.

미리보기는 템플릿 편집 결과를 이해하기 위한 기능이며 실제 콘텐츠를 작성하는 에디터가 아닙니다.

### 저장

명시적인 저장 버튼을 사용합니다.

옴니노드의 저장 정책과 충돌하는 자동 저장 동작을 임의로 추가하지 않습니다.

## 8. 어드민 초대 정보 입력 페이지

### 목적

프로젝트 관리자가 새로운 관리자를 초대하기 위해 필요한 정보를 입력하는 페이지입니다.

초대를 통해 관리자 계정을 생성하거나 프로젝트 관리 권한을 부여하는 흐름의 시작점입니다.

### 기본 정보 입력

필수 정보는 현재 인증·관리자 정책에 맞춰 구성합니다.

기본적으로 다음 항목을 사용합니다.

* 이메일
* 닉네임 또는 관리자명
* 대상 프로젝트

메일 주소는 관리자 계정의 로그인 ID로 사용됩니다.

### 권한 설정

초대 대상에게 어떤 프로젝트 권한을 부여할지 설정합니다.

권한 체계는 기존 프로젝트별 권한 정책을 그대로 사용하며 UI가 별도의 역할 체계를 생성하지 않습니다.

필요하다면 권한 목록을 그룹화하여 보여줍니다.

예:

* 문서 관리
* 카테고리 관리
* 템플릿 관리
* 월드 관리
* 관리자 관리
* 프로젝트 설정

### 권한 요약

우측 영역에는 현재 선택된 권한을 사람이 쉽게 이해할 수 있는 형태로 요약합니다.

사용자는 초대를 보내기 전에 대상 관리자가 무엇을 할 수 있는지 확인할 수 있어야 합니다.

### 초대 및 초기 계정 처리

초대가 승인 또는 처리되면 기존 인증 정책에 따라 계정을 생성합니다.

초기 비밀번호는 시스템에서 생성하고 메일로 발송하며, 최초 로그인 후 비밀번호 변경이 필요한 정책을 유지합니다.

UI에서 관리자가 직접 임시 비밀번호를 입력하도록 만들 필요는 없습니다.

### 초대 메일

초대 페이지에서 다음 정보를 확인할 수 있도록 합니다.

* 수신 이메일
* 대상 프로젝트
* 초대되는 권한 또는 역할
* 초대 안내 메시지

필요한 경우 사용자에게 전달될 메일의 주요 내용을 간략히 미리볼 수 있습니다.

### 주요 액션

페이지 하단의 Primary Action은 `초대 보내기`로 통일합니다.

취소는 Secondary Action으로 제공합니다.

# 공통 상단바 규칙

8개 화면 전체에서 동일한 상단바 체계를 사용합니다.

### 비로그인 상태

우측 영역에 다음 버튼을 표시합니다.

* 관리자 로그인

일반 문서 조회 등 공개 화면에서는 비로그인 사용자도 기본 UI를 사용할 수 있습니다.

### 로그인 상태

관리자가 로그인한 경우 로그인 버튼 대신 다음 정보를 표시합니다.

* 관리자 이름 또는 닉네임
* 이메일
* 필요 시 관리자 유형 또는 권한 표현
* 계정 관련 메뉴

계정 정보 영역은 버튼처럼 과도하게 강조하지 않고 현재 로그인 상태를 알려주는 정보 블록의 성격을 유지합니다.

### 공통 검색

상단바에는 필요에 따라 전역 검색을 배치할 수 있습니다.

검색 범위는 현재 Context에 따라 전체 시스템, 프로젝트, 월드 등으로 명확히 구분되어야 합니다.

# 공통 디자인 원칙

전체 UI는 **현대적인 전문 위키 및 설정 관리 도구**를 목표로 합니다.

* 밝고 중립적인 배경
* 얇은 Border 중심의 레이아웃
* 낮은 Shadow 사용
* Blue 계열의 절제된 Primary Color
* 문서 화면은 가독성 우선
* 관리 화면은 적절히 높은 정보 밀도 유지
* 판타지풍 장식 요소 사용 금지
* 카드를 필요 이상으로 남용하지 않음
* 선택·상태·위험 동작에만 Semantic Color 사용
* 동일 기능은 모든 페이지에서 동일한 UI 패턴 사용

이미지 시안은 레이아웃과 정보 구조를 이해하기 위한 설계 참고 자료이며, 이미지 생성 과정에서 표현된 임의의 샘플 문구·수치·기능은 실제 도메인 명세보다 우선하지 않습니다.

실제 구현 시에는 원격 저장소의 최신 `AGENTS.md`, `TODO.md`, 옴니노드 기본 지침 및 확정된 도메인 정책을 기준으로 구현합니다.
